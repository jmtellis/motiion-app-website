## Security migration

`supabase/migrations/20261102170100_authorize_library_member_hydration.sql` preserves the iOS/web RPC signature and card data shape while removing anonymous execution and enforcing current actor access. Active public profiles are available to authenticated callers. Private cards require self access or a real talent-authored submission in an owned/collaborated project. Missing profile accounts and moderated profiles are excluded. Existing profile data and share rows are not rewritten. Roster membership is not private-profile consent: owners can insert arbitrary profile IDs into lists. The final guard deliberately does not authorize private cards from bookmarks or roster shares.

The previous SECURITY DEFINER function was identical on staging and production and accepted any supplied professional profile ID without checking authentication or visibility. The final migration was applied successfully to **staging only**. The staging ledger includes the initial guard and a corrective function replacement that removed a roster-membership exception; the pending production file contains the final definition. Direct anonymous execution now returns a permission error; an unrelated authenticated user gets no private card. Owner/recipient roster reads remain functional. Final direct-JWT negative tests create a new owner roster, insert a known private profile ID, share the list, and confirm both owner and recipient still receive no private card. Self access is retained.

Production rollout: root must approve and apply this single shared migration to project `pygdxcscmebeqjxhzzuq`, once across the shared backend; do not apply separately from both repositories. Confirm anonymous execution denied, public authenticated card available, private unauthorized card absent, private ID added to an owned/shared roster still absent, shared roster accessible and revoked recipient denied. Production's existing industry entitlement trigger is separate from this hydration change. Staging does not establish that trigger's deployed subscription behavior; server-action Pro validation was exercised using the designated synthetic Pro fixture.
