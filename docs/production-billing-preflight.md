Only the exact active $59.99 USD monthly offer can start a new checkout. Existing open checkouts are reused only for this offer version. Previously purchased plans are not repriced or canceled.

## Native compatibility and privacy impact

Production `account_pro_status` was compared with the final migration's retained Apple/grant expression over **126 existing Auth accounts: 0 differences**. There is one active Industry grant and one active Talent grant, yielding one current Pro flag in each category; Community remains false. No currently trusted Apple subscription was present. The exact seven current/legacy Apple SKU IDs, three-minute Apple grace helper, plan-specific grants, and `{talent, industry, community}` boolean response are retained. The new Stripe branch requires trusted provider verification, Industry plan, active/trialing status and a finite unexpired period; it does not unlock Talent or Community.

Production has **48** professional projections, all with existing active public accounts; **8** are verified, none private/moderated. The proposed direct-table restrictive privacy policy therefore hides no currently public verified row in this snapshot. It prevents future private/moderated leakage. The hydration guard additionally removes anonymous direct RPC execution (currently allowed), while authenticated public-card access and genuine private submission relationships remain supported. Public website roster links use their separate authorized server path; their privacy checks were exercised on isolated staging. Recheck inventory immediately before applying material access-policy changes.

The deployed `delete_my_account()` currently checks only the actor and deletes Auth with cascades; it does not consult Stripe or cancel subscriptions. This explains a risk, not the cause of the existing orphan. A separate deletion guard/review is being tracked in the root release record; web deletion now checks actual provider state, and native/SQL protection must be included in the approved final release.
