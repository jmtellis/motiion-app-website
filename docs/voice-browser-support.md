# Voice search browser support and verification

Reviewed 2 November 2026. Both the typed-search microphone control and Navigator composer use the same capture hook. The typed query remains available for unsupported, denied, interrupted and failed captures. No universal browser-support claim is made.

## Capability and API decisions

- Capture requires a secure context, `navigator.mediaDevices.getUserMedia` and `MediaRecorder`. Feature detection happens after hydration and is repeated on the explicit microphone click. Browser permission can remain unanswered indefinitely; Cancel remains available and a late stream is stopped without applying its result. These behaviors follow the [getUserMedia contract](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia).
- Recording probes WebM/Opus, WebM, MP4 and Ogg/Opus at runtime. Engines without the MIME probe may select their default; actual recorder/chunk MIME is retained, validated and used for the filename. It is never relabeled as WebM. A positive probe does not guarantee sufficient runtime resources. See [MediaRecorder.isTypeSupported](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static) and [WebKit's MediaRecorder guidance](https://webkit.org/blog/11353/mediarecorder-api/). The latter establishes the MP4 path; its historical version list is not a current support guarantee.
- Browser `SpeechRecognition`/`webkitSpeechRecognition` is an optional interim preview. It is neither a capture prerequisite nor an authoritative final transcript. The recorded utterance goes through the existing authenticated transcription action so a partial preview cannot silently truncate a search. [SpeechRecognition remains limited in availability and may use a remote recognition service](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition).
- The recorder completion observer starts before recording. It waits for the final `stop` event even if `state` is already inactive, preserving the final audio chunk. The [recording specification](https://www.w3.org/TR/mediastream-recording/#dom-mediarecorder-stop) changes state synchronously and dispatches events asynchronously; [the stop event follows final dataavailable](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/stop_event).
- Device loss/permission revocation ends a track; [calling track.stop itself does not fire ended](https://developer.mozilla.org/en-US/docs/Web/API/MediaStreamTrack/ended_event). A device end or the one-minute limit finishes capture, releases media resources and shows **Recording ready**, with Use recording and Cancel. It no longer continues to display Listening after capture ends. Recorder errors produce retry/typed recovery.
- `NotAllowedError`/`SecurityError`, missing device, busy/unreadable device and unsupported recording each have useful recovery. Cancel during processing invalidates the result, so a late transcription cannot replace a newer query.

## No-speech recovery

An actual two-second silent WAV produced a hallucinated word from Whisper. The transcription action now requests the documented `verbose_json` response and rejects an entire recording only when **every segment has at least 0.9 no-speech probability**. This is a conservative product threshold informed by the reproduced failure, not a provider guarantee. Mixed speech/silence remains eligible; empty transcripts and malformed responses have separate errors. The model remains `whisper-1`; no catalog/model migration was introduced. [OpenAI's transcription API](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create) documents the accepted input formats and verbose segment fields.
