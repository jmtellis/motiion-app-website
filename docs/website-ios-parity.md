# Website and iOS parity

The current implementation and evidence live in [the delivery matrix](parity-delivery.md), with detailed [auth/onboarding](parity-auth.md), [projects/casting](parity-projects.md), [calendar/inbox/search/community](parity-calendar-inbox-search.md), [rosters and shared services](parity-product-surfaces.md), and [account roster access](parity-roster-access.md) records. These replace the earlier source-only parity report and sample-data checks.

Talent navigation includes Home, Discover, Opportunities, Inbox, Calendar and Portfolio. Industry navigation includes Home, Discover, Projects, Inbox, Calendar and Roster. Projects use Active, Drafts and Archived card views. Shared Home/Discover feeds and current iOS backend contracts remain the feature reference.

Booking agreements, signing and booking payments are removed from the website product. Historical backend records remain intact. Legacy URLs explain the retired scope and point to supported work. Casting selections, availability, confirmations and project coordination remain supported. Unrelated subscriptions and class enrollment billing remain in scope.

The improved [web design system](design.md) is implemented in shared runtime tokens and components. [The standalone reference](design.html) and authenticated `/admin/design-system` gallery document current states. Acceptance records explicitly distinguish automated checks, actual browser journeys, live authenticated integration and pending release validation.
